*Спецификация 10 взаимосвязанных подсистем на движке Godot 4.7+ Forward+*

## 1. СХЕМА ВЗАИМОДЕЙСТВИЯ 10 ПОДСИСТЕМ ДВИЖКА

Все системы функционируют по слабосвязанному принципу через шину событий (`EventBus`) и типизированные ресурсы (`Resource`):

```
                                  +-----------------------------+
                                  |     EventBus (Autoload)     |
                                  +--------------+--------------+
                                                 |
         +-----------------------+---------------+-----------------------+
         |                       |                                       |
         v                       v                                       v
+------------------+   +-------------------+                   +--------------------+
|   VoxelWorld     |   |   BiomeManager    |                   |    SoundManager    |
| (Чанки, Мешинг)  |   | (Шумы и Высоты)   |                   | (3D Аудио и Эхо)   |
+--------+---------+   +---------+---------+                   +---------+----------+
         ^                       ^                                       ^
         |                       |                                       |
+--------+---------+   +---------+---------+                   +---------+----------+
|  TerrainModifier |   |   BuildingSystem  |                   |   HorrorDirector   |
| (Копка и Сетка)  |   | (Конструкции)     |                   | (Dread State Mach) |
+--------+---------+   +---------+---------+                   +---------+----------+
         │                       │                                       │
         +-----------------------+---------------+-----------------------+
                                                 │
                                                 v
                                       +-------------------+
                                       | NarrativeManager  |
                                       | (Сюжет и Акты)    |
                                       +---------+---------+
                                                 │
                                                 v
                                       +-------------------+
                                       | SaveGameManager   |
                                       | (Дельты Чанков)   |
                                       +-------------------+
```

## 2. СПЕЦИФИКАЦИЯ 10 ПОДСИСТЕМ: ВХОДЫ, ВЫХОДЫ И ОТВЕТСТВЕННОСТЬ

### 1. Подсистема Генерации Мира (World Generation)
- **Класс**: `VoxelWorld` (`Node3D`).
- **Ответственность**: Асинхронное создание чанков $16 \times 16 \times 16$, быстрый Greedy Meshing с прямым 1D-индексированием, управление LOD и статическими коллизиями.
- **Входы**: Координаты игрока `Vector3`, сид генерации `world_seed: int`.
- **Выходы**: Меши чанков `ArrayMesh`, статические коллизии `ConcavePolygonShape3D`.
- **Зависимости**: `BiomeManager`, `WorkerThreadPool`.

### 2. Менеджер Биомов (Biome Manager)
- **Класс**: `BiomeManager` (`Resource` / RefCounted).
- **Ответственность**: 3D-шумовая интерполяция типов пород, высотное стратиграфическое зонирование (5 ярусов), температурно-влажностные карты.
- **Входы**: Координата вокселя `Vector3i`.
- **Выходы**: Идентификатор породы `BlockType: int`, параметры тумана и освещения.
- **Зависимости**: `FastNoiseLite`.

### 3. Модификатор Ландшафта (Terrain Modification)
- **Класс**: `VoxelModifier` (`Node`).
- **Ответственность**: Разрушение вокселей при ударе киркой/динамитом, мгновенное локальное обновление меша (re-mesh dirty sub-chunk) за $< 16\text{ мс}$, спавн дропа.
- **Входы**: Координата удара `hit_coord: Vector3i`, прочность инструмента.
- **Выходы**: Сигнал `block_broken(coord, type)`, спавн `DroppedItem`.
- **Зависимости**: `VoxelWorld`, `SoundManager`.

### 4. Строительная Система (Building System)
- **Класс**: `BuildingSystem` (`Node3D`).
- **Ответственность**: Размещение блоков, бревен, опорных балок и лестниц, проверка опоры (структурная стабильность конструкций).
- **Входы**: `RayCast3D` взгляда игрока, тип блока в хотбаре.
- **Выходы**: Сигнал `block_placed(coord, type)`.
- **Зависимости**: `VoxelWorld`, `InventorySystem`.

### 5. Менеджер Повествования (Narrative Manager)
- **Класс**: `NarrativeManager` (`Autoload`).
- **Ответственность**: Контроль смены Актов 0–V, инвентарь найденных записок, проверка условий концовок, трекинг 30 пасхалок.
- **Входы**: Сигналы взаимодействия от `InteractiveProp`.
- **Выходы**: Обновление `StoryStateResource`, вызов экранных субтитров.
- **Зависимости**: `EventBus`, `SaveGameManager`.

### 6. Литоакустическая Память (Audio Memory System)
- **Класс**: `SoundManager` (`Autoload`).
- **Ответственность**: Пространственное позиционирование звуков, кольцевой буфер эха (`LithicEchoBuffer`) с динамической задержкой от стен пещеры, расчет реверберации от объема залов.
- **Входы**: Позиция источника звука, громкость, материал удара.
- **Выходы**: Аудиопоток в `AudioServer` с параметрами DSP-ревербератора.
- **Зависимости**: `VoxelWorld` (рейкасты до стен).

### 7. Скрытый Режиссер Хоррора (Psychological Horror Director)
- **Класс**: `HorrorDirector` (`Node`).
- **Ответственность**: Расчет скрытого параметра `Dread Meter` ($0.0 .. 1.0$), планирование и триггер 15 аномалий EV-01..EV-15 с соблюдением кулдаунов и зон безопасности.
- **Входы**: Уровень освещенности игрока, время неподвижности, глубина $Y$, частота копки.
- **Выходы**: Запуск звуковых и визуальных аномалий (рассинхрон тени, шаги сзади).
- **Зависимости**: `PlayerController`, `SoundManager`, `WorldEnvironment`.

### 8. Менеджер Мировых Событий (World Events)
- **Класс**: `WorldEventManager` (`Node`).
- **Ответственность**: Управление глобальными фазовыми переходами (осушение шлюзов, запуск турбины) и циклическими ритмами (инфразвуковой прилив).
- **Входы**: Таймеры и триггеры сюжетных переключателей.
- **Выходы**: Изменение уровня воксельной воды, переключение освещения секторов.
- **Зависимости**: `VoxelWorld`, `NarrativeManager`.

### 9. Постоянство Мира (Persistent World State)
- **Класс**: `ChunkPersistence` (`RefCounted`).
- **Ответственность**: Сохранение ТОЛЬКО измененных («грязных») вокселей через RLE-компрессию, исключающее сохранение гигабайтов неизмененного процедурного шума.
- **Входы**: Список измененных координат вокселей в чанке.
- **Выходы**: Бинарные файлы дельт чанков `user://saves/chunks/chunk_X_Y_Z.dat`.
- **Зависимости**: `FileAccess`.

### 10. Сохранение и Загрузка (Save/Load)
- **Класс**: `SaveGameManager` (`Autoload`).
- **Ответственность**: Атомарная сериализация состояния игрока, инвентаря, позиции, флагов мира и дельт чанков. Защита от повреждения сейвов при сбоях.
- **Входы**: Команда сохранения / загрузки.
- **Выходы**: Файл `user://saves/save_slot_01.tres`.
- **Зависимости**: Все вышеперечисленные синглтоны.

## 3. БЮДЖЕТ ПРОИЗВОДИТЕЛЬНОСТИ (HARDWARE BUDGETS)

- **Целевая платформа**: ПК (минимальный таргет: GTX 1060 / 1660, Steam Deck 15W, 60 FPS стабильно).
- **Оперативная память (RAM)**: не более **2.2 ГБ** в пике (активный радиус прорисовки 6 чанков).
- **Видеопамять (VRAM)**: не более **2.8 ГБ** (текстурный атлас $512 \times 512$, нормальные карты $256 \times 256$).
- **Бюджет кадра**: Время мешинга одного чанка в пуле потоков $\le 4.5\text{ мс}$.
